# Operating System

Use this file when the user needs goals, management cadence, review loops, decision rights, or a company operating rhythm.

## Build the Rhythm Around Decisions

An operating system is not a meeting calendar. It is the repeated loop that turns priorities into actions, actions into data, and data into better decisions.

Design it in this order:

1. Define the few outcomes that matter this cycle.
2. Build a metric tree from business outcome to controllable drivers.
3. Assign owners to drivers, not just projects.
4. Set review cadence based on how fast the metric can move.
5. Make each meeting decide, unblock, or learn. Cancel meetings that only report.
6. Close each loop with owner, deadline, expected metric movement, and next review date.

## Goal System

Use goal methods quietly:

- Use a North Star only when one metric genuinely reflects delivered value and long-term business health.
- Use OKRs for cross-functional change where learning and prioritization matter.
- Use KPIs for stable operational responsibilities where consistent performance matters.
- Use input metrics for behaviors teams can control this week.
- Use countermetrics to prevent gaming, such as quality loss after speed improvements.

Translate goals into a short chain:

Outcome -> driver -> owner -> weekly action -> leading metric -> review decision.

## Cadence Design

- Daily: use only for operational control, incidents, launch rooms, support queues, fulfillment, or cash emergencies.
- Weekly: use for execution review, bottleneck removal, pipeline quality, churn response, cost variance, and hiring progress.
- Monthly: use for business review, budget versus actuals, customer cohort movement, process health, and team capacity.
- Quarterly: use for strategy, resource allocation, org design, major process changes, and capability gaps.

## Meeting Standards

Every recurring meeting needs:

- Decision owner.
- Pre-read or source dashboard.
- Fixed agenda tied to metrics.
- Escalation criteria.
- Decision log.
- Follow-up owner and due date.

Remove meetings that lack decisions, unblocking, learning, or accountability.

## Review Questions

- What moved and why?
- Which driver is off plan?
- Which assumption was wrong?
- Which owner needs a decision or resource?
- What will change before the next review?
- What will we stop doing?

## Failure Signals

- Teams discuss activity more than metric movement.
- Metrics are reported but no decision changes.
- Every cross-functional decision escalates to one person.
- Priorities change outside the cadence without explicit tradeoffs.
- Meetings multiply while execution speed declines.
- Owners are named for tasks but not for outcomes.
